# Pure PDF Viewer

A PDF viewer with tabs, search, and annotation, running as a **macOS app** and a
**web app** from one codebase.

**[Try the web app →](https://pujunru.github.io/PDF-Viewer/)**

The interface is a hand-drawn "pencil sketch" theme in pure grayscale, where
hierarchy flows downward: the selected item in each row becomes the background
of the row below it.

## Structure

```
packages/
  core/      Types, tab logic, and the shell<->viewer message protocol
  styles/    Design tokens + their two projections (RN StyleSheet, CSS vars)
  ui/        Every component, and the App shell itself
  viewer/    The pdf.js viewer document and its assets
apps/
  web/       Web entry point (Vite + react-native-web)
app/         macOS entry point (react-native-macos)
tools/       Build-time helpers (sample document generator)
```

## How the sharing works

The UI is written once against `react-native` imports. On macOS those resolve to
`react-native-macos`; on web the bundler aliases them to `react-native-web`, so
the same `StyleSheet.create` objects and the same components render in both.
`packages/ui/src/App.tsx` is the entire shell — the two entry points differ only
in what they inject into it.

Two things genuinely cannot be shared, and both are isolated behind an interface:

| Concern | macOS | Web |
|---|---|---|
| **File access** (`FileService`) | `NSOpenPanel` / `NSSavePanel` via a native module | File System Access API, falling back to `<input type=file>` on Safari/Firefox |
| **Viewer host** (`PdfViewport`) | `react-native-webview` | same-origin `<iframe>` |

`PdfViewport` is resolved by platform extension (`.native.tsx` / `.web.tsx`) —
RN's own convention, taught to Vite via `resolve.extensions`. Both
implementations expose the identical `post()` handle, so `App.tsx` never
branches on platform.

The viewer document is byte-identical across platforms: it detects whether its
host is a React Native WebView or a parent frame and picks its outbound channel
accordingly. `app/assets/pdfjs` is a symlink to `packages/viewer/src`, so the
macOS bundle and the web build ship the same file.

## Running

```bash
npm install

npm run web          # web dev server on :5173
npm run web:build    # production build

npm run macos        # macOS app
cd app && npx jest   # tests

python3 tools/make-sample-pdf.py   # regenerate the bundled sample document
```

## Continuous integration

| Workflow | Does |
|---|---|
| `web.yml` | Type-checks and builds the web app; deploys it to GitHub Pages on `main` |
| `macos.yml` | Builds the macOS app and uploads the unsigned `.app` as an artifact |

The macOS artifact is **unsigned** — macOS will refuse to open it on first
launch. Right-click the app and choose *Open* to run it anyway, or clear the
quarantine flag with `xattr -dr com.apple.quarantine PdfViewerApp.app`.

## Notes

- Saving annotations into the PDF (Phase 7 of the implementation plan) is not
  wired up on either platform yet; `FileService` already carries the write half
  of the interface for it.
- On Safari and Firefox, which lack `showSaveFilePicker`, saving degrades to a
  download — the platform offers no way to write a picked file in place.
- The bundled `sample.pdf` is generated by `tools/make-sample-pdf.py`, not
  copied from anywhere — the repo carries no third-party documents. The script
  writes the PDF by hand so no PDF library is needed to rebuild it.
